# GitLab Dashboard для VS Code

Расширение VS Code 1.95+: статусы и запуск GitLab pipeline, логи jobs,
сохраняемые фильтры и прогноз времени завершения по предыдущим запускам.

## Установка и подключение

1. **Extensions → … → Install from VSIX…** и выберите
   `gitlab-dashboard-*.vsix`.
2. Откройте доверенную папку проекта в VS Code.
3. Создайте в ней `.vscode/gitlab-dashboard.json`:

   ```json
   {
     "url": "https://gitlab.company.ru",
     "token": "glpat-ВАШ_ТОКЕН"
   }
   ```

4. Нажмите иконку GitLab Dashboard (контур лисы) на боковой панели Activity Bar
   или выполните **GitLab Dashboard: Открыть панель**.

Token — Personal Access Token GitLab со scope `api`. URL может содержать
подкаталог установки, например `https://host/gitlab`. После сохранения JSON
изменения подхватываются автоматически; изменение URL или токена сбрасывает
старое подключение и данные панели. Некорректный JSON отключает подключение до
исправления файла, а удаление файла сбрасывает настройки. Для файла доступны
проверка структуры и подсказки полей в редакторе.

**GitLab Dashboard: Настроить подключение** запрашивает URL и Token, проверяет
их через `GET /user` и записывает в этот же файл. При ошибке можно явно выбрать
«Сохранить всё равно». Пустое поле токена при повторной настройке сохраняет
текущий токен только для того же сервера. **GitLab Dashboard: Настройки**
открывает JSON; если файла ещё нет, создаёт пустой шаблон. В multi-root
workspace используется `.vscode/gitlab-dashboard.json` **первой папки**; в окне
без открытой папки настройка недоступна.

Токен хранится в этом JSON открытым текстом. Добавьте файл в `.gitignore`
проекта:

```gitignore
.vscode/gitlab-dashboard.json
```

В этом репозитории файл уже исключён из Git и из VSIX. Токен не передаётся в
webview, не включается в сообщения об ошибках JSON и не сохраняется в общем
состоянии окон. Запросы используют proxy и системные сертификаты extension host
VS Code (`http.proxy`, `http.proxySupport`, `http.systemCertificates`); redirect
не выполняется.

Все настройки находятся в `.vscode/gitlab-dashboard.json`:

| Поле             | Назначение                                                                          |
| ---------------- | ----------------------------------------------------------------------------------- |
| `url`            | HTTPS-адрес GitLab                                                                  |
| `token`          | Personal Access Token со scope `api`                                                |
| `favorites`      | необязательный массив URL проектов или `group/project`, по умолчанию `[]`           |
| `refreshSeconds` | необязательный интервал обновления, 5–3600 с, по умолчанию 15                       |
| `savedQueries`   | необязательный объект «название → запрос»; без него используются встроенные фильтры |

Добавление избранного и сохранение/удаление фильтров обновляют этот же файл.

## Проекты и pipeline

Панель собирает GitLab-репозитории из всех открытых окон VS Code через
встроенное расширение Git: HTTPS и SSH remotes, вложенные группы, одинаковые
проекты объединяются. Текущая ветка берётся прежде всего из окна, в котором
открыта панель. Окна обмениваются списком репозиториев через общую папку
расширения раз в минуту и при смене ветки.

Кнопки в заголовке панели: **Запустить pipeline**, **Обновить проекты**,
**Добавить проект**, **Настроить подключение**, **Настройки**. **Добавить
проект** принимает URL проекта, `group/project` или строку для поиска доступных
проектов на сервере. Для SSH-алиаса, имя которого отличается от hostname GitLab,
добавьте проект в избранные.

Пока панель видна, список и детали обновляются с заданным интервалом, проекты
пересканируются раз в минуту. В узкой панели (до 600 px) pipeline отображаются
карточками: проект, ветка, статус, ID и время создания доступны без
горизонтальной прокрутки. Выбор открывает детали; **← К списку** возвращает к
результатам и сохраняет запрос и выбор. Автообновление не переключает список
обратно на детали.

В широкой панели используется таблица. Колонки сортируются кнопками в
заголовках; строки выбираются мышью, стрелками вверх/вниз, **Home** и **End**.
Разделитель ширины перетаскивается мышью или меняется стрелками влево/вправо,
когда на нём фокус.

Выберите pipeline: появятся детали, прогноз, jobs по стадиям и лог. Действия
**Следить до завершения** и **Открыть в GitLab** находятся над деталями. Упавшая
job выбирается первой. Лог показывает ANSI-цвета, работающая job обновляется с
интервалом, большие логи ограничены хвостом в 2 097 152 символа. Поиск по логу:
поле в его панели или `Ctrl+F`, `Enter`/`Shift+Enter` переходят между
совпадениями. Выделенный текст копируется обычным `Ctrl+C`. В раскрываемом блоке
**Действия с логом** доступны **Обновить**, **Копировать**, **В редактор** и
**Job в GitLab**. Копирование и открытие в редакторе работают с логом без
ANSI-кодов; GitLab открывает полный лог. В списке pipeline `Ctrl+F` фокусирует
запрос, а в деталях — поиск по логу.

Сохранение, выбор и удаление запросов собраны в блоке **Сохранённые фильтры**
под поиском. Формы фильтрации и запуска поддерживают **Tab**/**Shift+Tab**
внутри формы и **Escape** для отмены; после закрытия фокус возвращается на
кнопку открытия.

## Поиск

Строка запросов и форма **Фильтры…** задают одну модель условий. **Enter**
применяет запрос, **Ctrl+Space** показывает подсказки ключей и значений.

```text
project:team/* branch:feature/* status:failed,running user:me after:24h
branch:@current after:7d
project:team/api,team/worker status:failed after:2026-10-01
sha:50f0acb7 source:push after:30d
name:"build pipeline" latest:true after:7d
text:"feature fix" after:7d
```

- `project`, `branch`: точные значения или маски `*` / `?`, несколько через
  запятую.
- `branch:@current`: текущая локальная ветка каждого найденного проекта.
- `status`: один или несколько статусов GitLab через запятую.
- `user`: username инициатора запуска; `me` означает пользователя токена.
- `sha`: полный commit SHA или hex-префикс длиной от 4 символов.
- `id`: числовой ID pipeline.
- `name`: название pipeline, поддерживает маски.
- `source`: источник, например `api`, `push`, `web`, `schedule`,
  `merge_request_event`.
- `after`, `before`: границы времени создания; ISO 8601 с часовым поясом,
  `YYYY-MM-DD` (UTC), `30m`, `24h`, `7d`.
- `latest:true`: последний подходящий pipeline каждой ветки среди загруженной
  истории.
- `text`: поиск по пути проекта, ID, ветке, SHA и названию. Текст без ключа тоже
  ищется.

Условия разных полей объединяются через И, значения одного поля — через ИЛИ.
Значения с пробелами заключаются в кавычки. Повтор ключа, некорректные статусы и
даты отклоняются с сообщением об ошибке.

Каждый запрос загружает первые 100 pipeline выбранных проектов. **Загрузить
ещё** переходит к следующим страницам; строка состояния показывает найденное,
просмотренное и полноту истории. **Остановить загрузку** отменяет текущий
запрос. История пагинируется в пределах снимка времени создания, чтобы новые
pipeline не сдвигали страницы.

Сохраните запрос под своим названием кнопкой **Сохранить фильтр**. В комплекте
есть «Мои запуски», «Ошибки за сутки», «Текущая ветка» и «Все за неделю».

## Запуск и уведомления

**Запустить pipeline** открывает форму: проект, серверная ветка, CI/CD variables
и прогноз. **Найти ветки** ищет по введённому тексту, поле также принимает
полное имя ветки. Запускается commit, который сейчас находится в этой ветке на
GitLab. Значения variables существуют только в открытой форме и не сохраняются
ни в настройках, ни в состоянии панели.

Созданный pipeline отслеживается автоматически. Для существующего нажмите
**Следить до завершения**. Отслеживание общее для всех окон, продолжается при
скрытой или закрытой панели и восстанавливается после перезапуска VS Code. Опрос
выполняет одно окно; если оно закрывается, работу подхватывает другое. Флажок
**Отслеживаемые** показывает такие pipeline независимо от поискового фильтра.

Уведомление появляется после итогового статуса и завершения всех jobs этого
pipeline, включая trigger jobs. Обязательные manual jobs требуют действия
пользователя; необязательные manual jobs не блокируют завершение. Повторное
завершение после retry даёт новое уведомление. Одно завершение уведомляется один
раз на все окна. Действия уведомления открывают pipeline в панели или в GitLab.

Если ответ на запуск потерян или сервер вернул 5xx, расширение сообщает о
неопределённом результате. Проверьте обновлённую историю перед повторным
нажатием «Запустить».

## Прогноз времени

Прогноз виден в форме запуска и в деталях работающего pipeline:

- медианная длительность и эмпирический диапазон P25–P75;
- ожидание runner отдельно от выполнения;
- оставшееся время и примерное время завершения;
- число примеров, использование других веток и отметка предварительной оценки.

Используются до 20 успешных запусков того же проекта и источника. Предпочтение
отдаётся текущей ветке; при малой выборке рассматриваются другие ветки. Когда
известны jobs текущего pipeline, сравниваются их имена, стадии и тип
обычная/trigger job. Длительность — реальное время `finished_at - started_at`,
не сумма параллельных jobs. История кэшируется в памяти на 5 минут.

При превышении обычного времени остаток оценивается по более долгим примерам.
Если превышена вся история или pipeline ждёт обязательного manual-действия,
остаток отображается как неизвестный. Это эмпирический ориентир, а не
гарантированное время. REST API не позволяет восстановить все прошлые ручные
паузы после того, как jobs уже выполнены; такие паузы могут влиять на
историческую длительность.

## Remote, доверие и данные

Расширение работает на стороне workspace (`extensionKind: workspace`), чтобы
видеть репозитории встроенного Git API; при Remote SSH запросы к GitLab идут с
удалённой машины. Для подключения из workspace-файла требуется доверие к папке
(Workspace Trust). Общее состояние окон хранится в папке globalStorage
расширения: `watches.json`, `monitor-lease.json`, `snapshots.json`,
`windows/*.json`. Токен и значения variables туда не попадают.
